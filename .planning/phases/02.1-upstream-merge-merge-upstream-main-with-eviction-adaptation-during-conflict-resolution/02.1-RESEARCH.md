**Researched:** 2026-04-08
**Domain:** Git merge conflict resolution, vLLM upstream integration, thought eviction adaptation
**Confidence:** HIGH

## Summary

This phase merges `upstream/main` (2527 commits ahead of the merge-base) into the `upgrade_vllm` branch. A dry-run merge reveals **14 files with conflicts** totaling **28 conflict regions**. The conflicts divide into two clear categories: (1) Phase-2-reconciled files where eviction code was appended to a v0.19 snapshot that upstream has since advanced beyond, and (2) files carrying pre-v0.19 eviction logic (scheduler, GPU runner, serving) that directly conflict with upstream's current code.

The merge is complicated by three gitignored files (`CLAUDE.md`, `vllm/vllm_flash_attn/__init__.py`, `vllm/vllm_flash_attn/flash_attn_interface.py`) that exist locally but are also tracked by upstream. These must be temporarily moved before the merge can proceed.

**Primary recommendation:** Execute the merge in a single `git merge upstream/main` operation. Resolve conflicts file-by-file using the following principle: accept upstream's code as the base, then re-apply eviction additions from the current branch. For Phase-2-reconciled files, the current branch version IS the conflict resolution reference. For Phase 3/4 files (scheduler, runner, serving), accept upstream's version and re-append eviction code adapted to current upstream APIs.

## Project Constraints (from CLAUDE.md)

- Manual file-by-file re-application chosen over git merge/apply -- volatile internals require structural adaptation
- Minimal adaptation only -- no refactoring to v0.19 patterns
- `UPDATE_MASK` at `b'\x06'` (verified non-colliding -- upstream WAKEUP is `b'\x05'`, nothing at `b'\x06'`)

## Architecture Patterns

### Conflict Resolution Strategy

There are exactly two resolution patterns needed for all 14 conflicting files:

**Pattern A: "Accept upstream + re-append eviction" (10 files)**
For files where Phase 2 already reconciled eviction code onto a v0.19 base, and the conflict is because upstream advanced beyond that base snapshot. Resolution: take upstream's version, then re-append the eviction additions.

**Pattern B: "Accept upstream wholesale" (4 files)**
For files where eviction logic belongs to Phase 3/4 scope (scheduler internal logic, GPU runner compute, serving wiring). Resolution: accept upstream's version completely. The eviction wiring for these files will be done in Phase 3 and Phase 4.

### msgspec Field Ordering (Critical)

The `EngineCoreOutput` struct uses `array_like=True, omit_defaults=True` -- field ordering is byte-significant for IPC serialization. Upstream has added new fields since Phase 2's snapshot:

| Field | Phase 2 Snapshot | Current Upstream |
|-------|-----------------|------------------|
| `num_external_computed_tokens` | Present | Present |
| `routed_experts` | Present | Present |
| `num_nans_in_logits` | Present | Present |
| `new_l2_norms` (ours) | Last field | Must remain last after all upstream fields |

Our `new_l2_norms` is already positioned correctly at the end. The auto-merge should preserve this, but it MUST be verified post-merge.

### EngineCoreRequestType Byte Values

Current upstream values: `ADD=b'\x00'`, `ABORT=b'\x01'`, `START_DP_WAVE=b'\x02'`, `UTILITY=b'\x03'`, `EXECUTOR_FAILED=b'\x04'`, `WAKEUP=b'\x05'`. Our `UPDATE_MASK=b'\x06'` remains non-colliding.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Conflict resolution | Custom merge scripts | `git merge` + manual resolution | Git's 3-way merge handles the 2527-commit delta correctly for non-conflicting files |
| File-by-file patching | `git apply` or `patch` | Manual conflict resolution with reference files | Upstream API changes make patches unreliable |

## Common Pitfalls

### Pitfall 1: msgspec Field Order Corruption
**What goes wrong:** A conflict resolution places `new_l2_norms` in the wrong position within `EngineCoreOutput`, breaking IPC serialization silently (no error, just wrong data).
**Why it happens:** The auto-merge might insert upstream's new fields after our `new_l2_norms` field instead of before it.
**How to avoid:** After merge, manually verify `new_l2_norms` is the absolute last field in `EngineCoreOutput`. Same for `enable_l2_norms`/`l2_norm_layers` in `SamplingParams` and `evictable_token_ranges_map` in `SchedulerOutput`.
**Warning signs:** L2 norms arriving as wrong values, or eviction not triggering despite `enable_l2_norms=True`.

### Pitfall 2: Accepting Upstream for Phase 3/4 Files Loses Eviction Context
**What goes wrong:** Phase 3/4 files (scheduler, runner, serving) need eviction code re-applied later, but the Phase 3/4 plans reference the pre-merge eviction code that no longer exists on the branch.
**Why it happens:** Accepting upstream wholesale for these files removes ALL eviction code from the working tree.
**How to avoid:** Before accepting upstream's version, save the current eviction-containing versions as reference files (or rely on git history via `git show HEAD~1:path/to/file`). Phase 3/4 plans should reference the pre-merge commit for eviction code.
**Warning signs:** Phase 3 planner cannot find reference eviction code.

### Pitfall 3: Gitignored Files Blocking Merge
**What goes wrong:** `git merge` refuses to proceed because gitignored local files would be overwritten by tracked upstream files.
**Why it happens:** Our `.gitignore` excludes `CLAUDE.md` and `vllm/vllm_flash_attn/*`, but upstream tracks these files.
**How to avoid:** Temporarily move the gitignored files before merging, restore after.
**Warning signs:** `error: The following untracked working tree files would be overwritten by merge`.

### Pitfall 4: input_processor.py Request ID Change
**What goes wrong:** Our branch disabled UUID suffix on request IDs (`request.request_id = f"{request.external_req_id}"`), but upstream now has a proper `VLLM_DISABLE_REQUEST_ID_RANDOMIZATION` env var.
**Why it happens:** Original eviction code needed stable request IDs; upstream solved this differently.
**How to avoid:** Accept upstream's approach (env var controlled), ensure eviction tests set the env var when needed.
**Warning signs:** Request ID mismatch between orchestrator and L2NormCache.

### Pitfall 5: Merge Commit Size Makes Review Difficult
**What goes wrong:** 2527 upstream commits produce massive diff, making it hard to verify eviction code survived.
**Why it happens:** Upstream vLLM is very actively developed.
**How to avoid:** After merge, run targeted verification: `git diff HEAD -- <eviction-file>` for each eviction-modified file. Verify eviction test files are present. Verify eviction imports work.
**Warning signs:** Any eviction file missing or containing conflict markers.

## Merge Execution Procedure

### Step 1: Pre-merge Setup
```bash
# Save reference commit for Phase 3/4 eviction code lookup
git rev-parse HEAD  # Record this as PRE_MERGE_REF

# Move gitignored files that block merge
mv CLAUDE.md CLAUDE.md.bak
mv vllm/vllm_flash_attn/__init__.py /tmp/flash_init.bak
mv vllm/vllm_flash_attn/flash_attn_interface.py /tmp/flash_iface.bak
```

### Step 2: Execute Merge
```bash
git merge upstream/main --no-edit
# This will report 14 conflicting files
```

### Step 3: Resolve Conflicts (by category)

**Pattern A files** -- for each: open file, find conflict markers, keep upstream's code as base, re-append eviction additions after upstream's code. Use `git show HEAD:path/to/file` to see our pre-merge version for reference.

**Pattern B files** -- for each: `git checkout upstream/main -- path/to/file` to accept upstream wholesale.

### Step 4: Post-merge Restoration
```bash
# Restore our CLAUDE.md (not upstream's)
mv CLAUDE.md.bak CLAUDE.md

# Flash attn files -- keep upstream's tracked versions
# (our gitignored copies are older)
```

### Step 5: Verify
```bash
# No conflict markers remain
grep -r "<<<<<<" vllm/ tests/ --include="*.py" | head

# Eviction modules still importable
python -c "from vllm.thought_eviction import orchestrator, segmenter, strategies, block_utils"

# Key eviction fields present
python -c "from vllm.v1.engine import EngineCoreRequestType; print(EngineCoreRequestType.UPDATE_MASK)"

# Eviction test files exist
ls tests/eviction/
```

### Step 6: Commit
```bash
git add -A
git commit  # Merge commit message auto-generated by git
```
